# Swamp Murlocs 1.2.2 — пустое болото и прозрачный фон

Рисованный Twitch-оверлей для OBS (1920×1080), Electron 45.2.3. Неофициальный фан-проект; не продукт Blizzard/Twitch.

## Что нового
- Мурлок с ником появляется, когда Twitch IRC присылает вход в чат (JOIN) или новое сообщение. Счётчик зрителей Helix не создаёт персонажей: анонимных зрителей эфира Twitch не показывает. PART убирает мурлока. Вход самого аккаунта оверлея в комнату персонажа не создаёт.
- Тип и раскраска вычисляются стабильным versioned hash Twitch user ID, независимо от ника и перезапуска. При редком отсутствии IRC user-id используется login; при получении ID привязка уточняется. Коллизии внешности возможны: доступно 100 сочетаний.
- По умолчанию максимум 20 видимых именных мурлоков; лимит включает исчезающих. При переполнении самый давно писавший уходит за 1,2 секунды, новый ждёт освобождения места. Без сообщений 15 минут — уход с fade. Настройки: 1–50 персонажей, 1–1440 минут.
- Редактируемый список ботов, без учёта регистра: Nightbot, StreamElements, Streamlabs, Moobot, Fossabot, Wizebot, Botrix, SoundAlerts, Sery_bot. Список можно очистить.
- Пока никто не вошёл в чат и не написал, на экране только болото, без запасных мурлоков. Сохранены 100 раскрасок, дыхание/моргание/действия, туман, пыль и 8 кадров солдат; направления ltr/rtl/alternate/random, очередь, старые триггеры и debug.
- Сообщения показываются WC-подобными облачками на 5 секунд (2–15 в настройках), до 140 Unicode-символов с многоточием. До 3 ожидающих сообщений у каждого мурлока; при переполнении старейшее ожидающее заменяется. Ссылки скрываются как [ссылка скрыта], сообщения с ! в начале не показываются. Эмоуты — текстом. Очень длинный текст визуально ограничен тремя строками.
- Текст существует только в ограниченной памяти IRC/оверлея, не сохраняется на диск, не попадает в лог/диагностику и не воспроизводится при переподключении. Приложение не умеет отправлять сообщения в Twitch.

## Подключение
1. Полностью закройте прежнюю версию через трей → «Выйти». Не запускайте две версии одновременно. Настройки приложения хранятся отдельно; файлы 1.1.1/1.2.0 не изменяются.
2. Включите Twitch, укажите канал, Client ID и access token. Для числа зрителей подходит app/user token. **Для IRC-ников и сообщений нужен user access token того же Client ID со scope chat:read**. Имя IRC-аккаунта определяется через официальный oauth2/validate, вручную его вводить не нужно. App token не читает чат; статус «нужен токен» виден в debug.
3. Сохраните настройки и дождитесь «HTTP-сервер работает». Скопируйте фактический URL в OBS Browser Source, 1920×1080. Обычно порт 8766, при занятости 8767–8785. После обновления очистите/обновите кэш источника.
4. При открытии OBS болото пустое. Ник появляется по новому JOIN или сообщению, не из числа зрителей и не задним числом. Кто уже сидел в чате до подключения, не виден, пока не напишет. На крупных каналах JOIN/PART могут не приходить, но PRIVMSG работает независимо.
5. Включите «Режим отладки» при проблемах. Отдельно включается HUD, доступны лог, HTTP/IRC/SSE-статус, счётчики, перезапуск сервера и безопасный отчёт.

Токен хранится отдельно: Keychain/DPAPI, если доступно шифрование ОС, иначе ограниченный локальный файл с предупреждением. В исходниках/архивах токенов нет. OAuth-автопродления нет. Старый таймер Electron остаётся uptime эфира, не персональным watch time.

## Демо
Откройте демо из настроек. N — пять вымышленных участников, Q — сообщение одному из них, C — плавно убрать. E — пробег по настройке, L/R — направления, V — порог зрителей, T/W — время, H/M/S/B/P — прежние действия. В производственном OBS горячие клавиши демо выключены.

## Обновления
Источник: публичные GitHub Releases **Jommmain/Twitch-overlay**. В приложении нет GitHub-токена.
- «Проверять при запуске» включено по умолчанию; «Автоматически скачивать» выключено.
- Установленная Windows **NSIS** версия использует electron-updater 6.8.11, GitHub provider и latest.yml. Опция автоскачивания применяется к следующей проверке. Установка только по кнопке «Установить и перезапустить» после эфира, без принудительного прерывания OBS и без скрытой установки при выходе.
- Windows portable и неподписанный macOS только проверяют версию, уведомляют и открывают страницу скачивания. Самозамены нет.
- Репозиторий приватный/релиз отсутствует/сеть недоступна — честная ошибка, без встроенного токена и без подмены версии. Если репозиторий станет приватным, потребуется отдельный безопасный публичный feed или другая схема доставки.
- В этом локальном выпуске **NSIS не собран**: Linux-хост не имеет Wine, установка Wine недоступна из-за ошибок Debian-репозитория. Полный NSIS/latest.yml должен собрать приложенный Windows CI до публикации. Исходники контроллера и mock-тесты готовы, но обновление Windows→Windows не проверено. Не публикуйте latest.yml, указывающий на отсутствующий Setup.exe.

## Запуск и сборка из исходников
Требуется Node.js 22+ и npm. Из папки desktop:
```bash
npm ci
npm test
npm start
```
Тесты оверлея: `node --test overlay/tests/*.test.mjs` из корня.
```bash
cd desktop
npm run dist:win    # Windows: NSIS + portable; Linux требует Wine для NSIS
npm run dist:mac    # macOS arm64 .app, unsigned
npm run dist:linux  # Linux .dir для smoke QA
```
Команды сборки используют `--publish never`, ничего не публикуют. `desktop/build/` содержит необходимые иконки, не результат сборки. Секреты/пользовательские настройки нельзя добавлять в Git.

`.github/workflows/release.yml` подготовлен для **будущего явного запуска владельцем через push тега v<version>**: native Windows NSIS/portable + macOS arm64 ZIP, GitHub Release и update metadata. Он здесь только сохранён как исходник, не запускался. Публикация релиза — отдельное внешнее действие. Репозиторий уже содержит README, поэтому загрузка исходников должна идти в новую ветку, не перезаписывая main.

## macOS / предупреждения ОС
Сборка arm64, не Intel. ZIP сохраняет framework symlinks и executable bits. Сборка unsigned, без notarization; Gatekeeper может блокировать. Windows unsigned тоже может вызвать SmartScreen. Нативный запуск Windows/macOS, настоящее OBS/Twitch, Keychain/DPAPI/трей/автозапуск и производительность на вашем компьютере не проверены. На Linux проверен реальный packaged asar-main, HTTP/SSE и debug. UI/updater-тесты используют mock IPC/события, не настоящую установку обновления.
